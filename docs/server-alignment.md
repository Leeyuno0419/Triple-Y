| 8 | **화각 밖 예측** | ✅ 상세 A-07, 여유 시 2순위(도로 예측). MVP 아님 | 핵심 기능으로 구현 | 우선순위 조정 (4장) |

### 조영준과 먼저 정할 것
1. `timeline.json` **최종 필드명**(flow 초안의 `flow_*` 접두사 등)과 밀도·예측 필드 추가 위치
2. WebSocket 메시지 형태 (타임라인 재생을 서버가 하므로 **무엇을 1초마다 보내는지**)
3. 서버가 판정해서 내려줄 값 (`grade`, 알림) 과 단계 이름

## 1. 확인된 규격

### 1.1 흐름 모듈 출력 (flow 초안 🟡) — `src/flow/run_flow.py`, `timeline_flow.py`
```jsonc
{
  "zone_id": "demo-zone-01",
  "camera_id": "...",
  "rate_hz": 1,
  "flow_estimator": "farneback",
  "seconds": [
    { "t": 0,
      "cells": [{
        "cell_id": "c-0412",
        "flow_vx": 0.21,          // 셀 평균 지면 속도 m/s
        "flow_vy": -0.05,         // m/s
        "flow_instability": 0.006,// 속도 분산 m²/s²
        "flow_pressure": 0.026,   // 군중 압력 ρ×분산, 1/s²  (밀도가 없으면 null)
        "flow_counterflow": 0.1,  // 역방향 비율 0~1
        "flow_quality": 340       // 유효 픽셀 수(정수). 기준(기본 200) 미만이면 위 값들은 null
      }]
    }
  ]
}
```
- `NaN`은 쓰지 않고 `null`로 쓴다 (`allow_nan=False`). 셀·구역 집계값만 담고 픽셀 흐름장·좌표는 담지 않는다 (✅ 개인정보 원칙).
- 밀도(ρ), 60초 뒤 ρ, 경계 유입량 필드는 **아직 이 초안에 없다** (counting·predict가 채울 자리).
- 기획서는 `timeline.json`을 "zone_id, camera_id, 초별 셀 상태(ρ, V, Var(v), P, 경계 유입량, 60초 뒤 ρ)"라고만 적고 **정식 JSON 예시는 없다.**

### 1.2 구역 상태 메시지 (상세 5.6 — 축소 전 계획, 참고용)
```jsonc
{ "zone_id": "demo-zone-01",
  "frame_ts": "2026-11-27T21:38:14.950+09:00",
  "cells": [{"cell_id":"c-0412","density":4.3,"vx":0.21,"vy":-0.05,"speed_var":0.006,"pressure":0.026,"turbulence":true}],
  "predictions": [{"edge_id":1532,"horizon_s":60,"density":3.4}],   // 도로 링크 단위 — v3.0에서 제외
  "model": {"counter":"p2pnet-vgg16","flow":"farneback"} }
```
- 채널(상세 5.6, 축소 전): `WS /ws/map`(셀 등급·예측, 1Hz), `WS /ws/alerts?zone={id}`(재연결 시 미확인 알림 재전송), `POST /api/alerts/{id}/ack`.
- 기획서 v3.0은 확인 기록을 **로그 파일**에 남긴다고 했으므로 위 DB·Redis 구조는 그대로 쓰지 않는다 (확인 필요).
- 메시지마다 `frame_ts`를 실어 **단말 수신 시각과의 차이로 지연(p95 ≤ 5초)을 잰다** (상세 5.4, 기획서 1.2 E8).

### 1.3 기타 확정 사항 ✅
- 셀: **2m × 2m**, 밀도는 보행 가능 면적 기준 명/m². 평활화 ρ* = 0.3·ρ + 0.7·ρ*(이전) (가정).
- 위험 단계 (기획서 3.2): 정상 <3, 주의 ≥3, 경계 ≥4, 심각 ≥5 **또는 불안정 지표 기준 초과(가정)**. 기준값 P = ρ×분산 > 0.02/s² (상세 3.4).
- 알림 수용 기준 (기획서 4.3): 단계 상승/유입 경보/경계·심각 상승 시 **5초 안에** 표시, 확인 기록 남김.
- 구역 ID와 카메라 ID는 처음부터 포함 (영상·구역 추가를 등록 작업으로 만들기 위해).
- 일정: G0 11-10, **G1 11-13(밀도 → timeline.json → 대시보드)**, G2 11-18, 코드 동결 11-19.

## 3. 서버(조영준)와 정할 질문

**Q1. 지도 화면을 MVP에 넣는가?** 기획서 v3.0은 "지도·도로망"을 제외하고 "탑뷰·지도 표시"를 여유 시 3순위로 뒀다. MVP 화면은 *영상 위 셀 히트맵*이다.
→ 선택지: (a) 지도 뷰는 여유 시 기능으로 두고 **영상 + 히트맵**을 먼저 만든다 (권장, G1이 11-13), (b) 팀이 지도를 다시 범위에 넣는다. 지도에 셀을 그리려면 **셀의 위·경도(또는 카메라 호모그래피와 카메라 좌표)** 가 필요하다 (Q9).

**Q2. 재생 방식과 WebSocket 메시지.**
- Spring Boot가 `timeline.json`의 `seconds[t]`를 1초마다 보내는 것으로 이해했다. 그렇다면 메시지는 `seconds[t]` 한 개 + `frame_ts` + 서버가 판정한 `grade`·알림으로 충분한가?
- 순수 WebSocket(`/ws/map`, `/ws/alerts?zone=`)인가 STOMP인가? (상세의 경로는 순수 WS 기준)
- 연결 직후 **구역·셀 메타**(cell_id 목록, 위치)를 어떻게 받는가? (REST 한 번 / 첫 메시지)
- 재생 제어: 재생·일시정지·**구간 이동(seek)** 을 서버가 지원하는가, 클라이언트가 받은 걸 저장해 되감는가? (현재 화면은 슬라이더로 과거를 본다)
- 영상(`E05_035` 등)과 히트맵을 맞추려면 클라이언트가 영상 재생 시각과 `t`를 맞춰야 한다. 영상은 누가 어디서 제공하나?

**Q3. 위험 단계 판정은 서버, 이름은?** 기획서대로 서버가 판정(히스테리시스 포함)해서 `grade`(구역)와 셀별 `grade`를 내려주면 클라이언트는 임계값 판정을 없앤다. 이름은 기획서 기준 **경계**로 통일할지(현재 화면은 "경고").

**Q4. 알림 메시지.** 서버가 만드는 알림의 필드: `id`, `zone_id`, `level`, `reason`(등급/유입/불안정), `created_at`, `acked_at`(상세 DB 표 기준). 확인(ack) API 형태와, 재연결 시 미확인 알림 재전송 여부.

**Q5. 지연 측정.** `frame_ts`(ISO, 서버 재생 시각)를 매 메시지에 넣는 것으로 하고, 클라이언트는 수신 시각과의 차이를 기록한다 (E8). 시계 동기(NTP) 기준은?

**Q6. 배포.** 개발 CORS/Origin(`http://localhost:5173`), 운영 `wss`, API 경로 prefix(`/api/`). 카카오 도메인 등록은 Q1에 따라 필요 여부가 달라진다.

## 4. AI(이유노·조영준)와 정할 질문

**Q7. 밀도·예측·유입 필드 이름과 위치.** 셀 레코드에 `density`(ρ, 명/m²), `density_pred_60`(60초 뒤 ρ), 구역 단위 `boundary_inflow`(경계 유입량, 명/s) 를 어떻게 부를지. flow 초안의 `flow_*` 접두사 규칙을 따를지.

**Q8. 예측 모듈의 입출력을 기획서에 맞춘다 (나예린).** 현재 구현과의 차이:
- 기획서: **최근 30초 ρ → 60초 뒤 ρ**, 기준선 *현재값 유지*·*직선 추세*, 상승/급변 구간 분리 공개, 합격 기준 없음. 상세는 흐름 외삽이 기준선보다 **20% 이상** 좋아야 채택.
- 지금: 마지막 프레임 1장과 흐름으로 30/60/120/300초. `evaluate.py`는 *정지(현재값 유지)* 기준선만 있다.
- 할 일: 기본 horizon을 60초로, 입력에 30초 기록 사용(또는 최근 프레임의 흐름 평균), `evaluate.py`에 *직선 추세* 기준선과 상승/급변 구간 분리 추가. 화각 밖 도로 예측(A-07)은 여유 시 2순위로 두고 코드는 유지.

**Q9. 셀 배치 정보 (이유노, `infra/`).** `cell_id` → (행, 열) 또는 영상 좌표/위경도 대응표, 보행 가능 면적, 구역 경계. 히트맵을 영상 위에 그리려면 **셀의 영상 좌표 사각형**(호모그래피 역변환)이 필요하고, 지도에 그리려면 위경도가 필요하다.

**Q10. 화각 밖 셀 표현.** 영상 화각 밖은 셀 자체가 없는 것인지(셀 목록에 없음), `null`인지. 우리 `null = 화각 밖` 가정을 바꿔야 할 수 있다. `flow_quality` 미달 셀(값 null)은 "관측 불가"로 해석하면 되는지.

**Q11. 평가용 데이터.** `E04_070`(60초 예측 검증, 437초) 등으로 만든 연속 `timeline.json`을 받으면 `python -m src.predict.evaluate`로 바로 측정한다.

## 5. 합의 전에 내가 할 수 있는 준비 (제안)
규격이 확정되기 전에도 **어댑터 한 곳**만 만들어 두면 나머지 코드는 건드리지 않아도 된다.

| 할 일 | 내용 | 파일 |
|---|---|---|
| 어댑터 (web) | CrowdSight `timeline.json`/WS 메시지 → 내부 `Timeline` 변환: `t`→ISO, m/s→셀/초, 셀 목록→격자, `density_pred_60`→`predicted` 프레임 | `web/src/lib/adapters/` (신규), `liveFeed.ts` |
| 어댑터 (predict) | 같은 변환의 Python 판 | `src/predict/adapter.py` (신규) |
| 서버 판정 반영 | `grade`가 오면 클라이언트 판정 대신 사용 | `web/src/lib/density.ts` |
| 알림 | 서버 알림 수신, 파생 로직 제거 | `web/src/lib/alerts.ts` |
| 영상 + 히트맵 뷰 | Q1 (a)로 결정되면 `<video>` 위 셀 사각형 오버레이 | `web/src/views/` |
| 예측 정렬 | Q8 | `src/predict/*`, `config.yaml` |

규격에 맞춘 **샘플 `timeline.json`** 을 하나 만들어(필드는 flow 초안 기준) 팀과 확인하고 싶다면 알려 달라.
