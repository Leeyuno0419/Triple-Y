# CrowdSight 용어 사전

> 컴퓨터 기초만 아는 사람을 기준으로, 이 프로젝트에서 나오는 낯선 용어를 쉽게 풀었다.
> 각 용어는 **쉬운 설명**과 **우리 프로젝트에서 어디에 쓰이는지**를 함께 적었다.
> 처음 읽는다면 0장의 흐름 그림을 먼저 보고, 모르는 단어가 나올 때 찾아보면 된다.
> 기획서(`docs/proposal.md`)를 읽는 중이라면 8장에 기획서 장 순서대로 추가 용어를 모아 두었다.

---

## 0. 한 장으로 보는 흐름

```
CCTV 영상
  │  ① 머리 찾기 (P2PNet)          → 사람 머리 위치에 점을 찍는다
  │  ② 바닥 지도로 옮기기 (호모그래피) → 비스듬한 화면을 위에서 본 지도로 편다
  │  ③ 칸 나누기 (셀)               → 바닥을 2m×2m 칸으로 나눠 칸마다 사람 수 ÷ 면적
  │  ④ 움직임 재기 (광학 흐름)        → 사람들이 어느 쪽으로 얼마나 빨리, 얼마나 제각각 움직이나
  │  ⑤ 60초 뒤 예측                  → 지금 추세로 1분 뒤 밀도를 짐작
  ▼
timeline.json (1초마다의 숫자 기록표)
  ▼
서버가 1초씩 재생하며 위험 등급 판정 → 상황실 화면에 히트맵·그래프·알림
```

## 1. 군중 안전 용어

| 용어 | 쉬운 설명 | 우리 프로젝트에서 |
|---|---|---|
| 밀도 (명/㎡) | 바닥 1㎡(가로세로 1m 정사각형)에 서 있는 사람 수. 엘리베이터 바닥이 약 2~3㎡다 | 가장 기본 지표. 3명 이상이면 "주의" |
| 임계 밀도 | 이 선을 넘으면 군중이 스스로 움직일 수 없게 되는 밀도. 대략 1㎡당 6명 이상 | 그 전에 알리는 것이 목표 |
| 군중난류 | 아주 빽빽한 군중이 파도처럼 한쪽으로 쏠렸다 되돌아오는 현상. 사람이 넘어지고 압사가 생기는 직전 단계 | 감지하고 싶은 위험 신호 |
| 속도 분산 (Var(v)) | 사람들 움직임이 얼마나 제각각인지. 모두 같은 방향·속도로 걸으면 0에 가깝고, 이리저리 밀리면 커진다 | 불안정 지표 계산에 쓴다 |
| 군중 압력 (P) | 밀도 × 속도 분산. "빽빽한데 마구 흔들린다"를 숫자 하나로 표현한 것. 2007년 메카 압사 사고 연구에서 나온 지표 | 불안정 지표. 0.02를 넘으면 위험 신호 (가정) |
| 역방향 비율 | 셀 안에서 대다수와 반대로 움직이는 비율. 사람이 서로 엇갈리면 높아진다 | `counterflow` 필드 |
| 경계 유입 / 유입 비율 | 화면 가장자리에서 안쪽으로 들어오는 움직임의 비율. 사람이 계속 밀려 들어오는지 본다 | 밀도가 오르기 전에 미리 알리는 "유입 경보" |
| 위험 등급 | 정상(3명 미만) / 주의(3명 이상) / 경계(4명 이상) / 심각(5명 이상) | 서울경찰청 골목 기준을 따랐다 |
| 구역 / 셀 | 구역 = 카메라 하나가 보는 골목 전체. 셀 = 구역 바닥을 2m×2m로 나눈 한 칸 | 밀도는 셀마다, 등급은 구역 단위 |
| 보행 가능 면적 | 셀 안에서 실제로 사람이 설 수 있는 바닥 넓이. 벽·건물은 뺀다 | 밀도 = 사람 수 ÷ 이 면적 |

## 2. AI·영상 용어

| 용어 | 쉬운 설명 | 우리 프로젝트에서 |
|---|---|---|
| AI 모델 | 예시를 많이 보고 규칙을 스스로 익힌 프로그램. "사진을 넣으면 머리 위치를 내놓는 함수"라고 생각하면 된다 | P2PNet |
| 학습 / 추론 | 학습 = 정답이 달린 사진으로 모델을 가르치는 과정. 추론 = 다 배운 모델로 새 사진에 답을 내는 과정 | 우리는 학습하지 않고 추론만 한다 |
| 가중치 | 학습이 끝난 모델의 "기억". 수백만 개의 숫자가 든 파일(`.pth`) | 공개된 `SHTechA.pth`를 받아 쓴다. 학술용이라 저장소에 올리지 않는다 |
| 딥러닝 | 여러 층으로 쌓은 인공신경망으로 학습하는 방법. 사진 인식에 강하다 | P2PNet이 딥러닝 모델 |
| 크라우드 카운팅 | 사진 속 사람 수를 세는 AI 분야 | 우리 문제의 학술 이름 |
| P2PNet | 사람 머리마다 점 하나를 찍어 주는 모델(2021년, Tencent). 점이라서 바닥 좌표로 옮기기 쉽다 | 인원 추정의 주 모델 |
| VGG16 | 사진의 특징(윤곽·무늬)을 뽑아내는 유명한 기본 신경망. P2PNet의 "눈" 역할 | P2PNet 안에 들어 있다 |
| 밀도 맵 방식 | 점 대신 "여기쯤 사람이 0.3명" 같은 흐릿한 지도를 내놓는 방식 (예: DM-Count) | 오차가 크면 쓸 대체 후보 |
| 검출 방식 (YOLO 등) | 사람마다 네모 상자를 그리는 방식. 빽빽하면 가려진 사람을 놓친다 | 그래서 쓰지 않았다 |
| 점수 / 판정 기준 (threshold) | 모델이 점마다 "머리일 확률"을 0~1로 준다. 기준(예: 0.4)보다 높은 점만 사람으로 센다 | 영상마다 E2로 고른다 |
| 축소 배율 (scale) | 영상을 몇 배로 줄여 모델에 넣는지. 0.5면 가로세로 절반 | CCTV 머리가 학습 사진보다 커서 줄여야 잘 센다 |
| 오탐 / 미탐 | 오탐 = 사람이 아닌데 사람으로 셈. 미탐 = 사람인데 놓침 | 오차의 두 원인 |
| 가려짐 | 앞사람에 뒷사람이 가려져 안 보이는 것. 빽빽할수록 심하다 | 장마다 가려지는 사람이 달라 5장 평균을 낸다 |
| 프레임 / fps | 영상은 사진을 빠르게 넘긴 것이고, 그 사진 한 장이 프레임. fps = 1초에 몇 장인지 | 우리 영상은 30fps |
| 해상도 / 픽셀 | 픽셀 = 화면을 이루는 작은 점 하나. 1920×1080은 가로 1920개, 세로 1080개 | 영상 좌표의 단위 |
| 광학 흐름 (Farneback) | 연속한 두 프레임을 비교해 화면의 각 부분이 어느 쪽으로 몇 픽셀 움직였는지 계산하는 방법. AI가 아닌 고전 알고리즘 | 사람들의 움직임(속도·방향) 측정 |
| CPU / GPU | CPU = 일반 계산 장치. GPU = 그래픽 카드. 같은 계산을 동시에 많이 해서 AI가 수십 배 빠르다 | 지금은 CPU로 돌려 느리다 |
| 데이터셋 | AI를 가르치거나 시험하려고 모아 둔 사진·영상과 정답 묶음 | ShanghaiTech, AI Hub |
| ShanghaiTech A / B | 사람 수 세기 분야의 대표 시험 문제집. A = 아주 빽빽한 인터넷 사진, B = 상하이 거리 사진 | E1에서 모델 성능 확인 |
| AI Hub | 정부(과학기술정보통신부)가 운영하는 공공 AI 데이터 사이트 | 시연용 CCTV 영상을 받은 곳 |
| 정답 (GT, Ground Truth) | 사람이 직접 확인한 진짜 값. AI 결과를 채점하는 기준 | E2에서 머리를 직접 클릭한 것 |
| 라벨 / 라벨링 | 데이터에 정답을 붙이는 것, 또는 붙은 정답 | E2 클릭 도구 |
| 비식별화 | 얼굴을 흐리게 하는 등 누군지 알 수 없게 처리한 것 | AI Hub 영상은 얼굴이 흐려져 있다 |
| 미세조정 | 이미 배운 모델을 우리 데이터로 조금 더 가르치는 것 | 여유가 있을 때 할 일 |

## 3. 좌표·기하 용어 (바닥 지도 만들기)

| 용어 | 쉬운 설명 | 우리 프로젝트에서 |
|---|---|---|
| 영상 좌표 | 화면 위 위치를 픽셀로 나타낸 것. (가로 몇 번째, 세로 몇 번째) | P2PNet이 주는 머리 점 |
| 바닥(지면) 좌표 | 실제 바닥 위 위치를 미터로 나타낸 것. 위에서 내려다본 지도라고 생각하면 된다 | 셀을 나누는 기준 |
| 원근 | 멀리 있는 것이 작게 보이는 효과. 같은 2m라도 화면 위쪽(먼 곳)에서는 짧게 보인다 | 화면 픽셀로 바로 넓이를 잴 수 없는 이유 |
| 호모그래피 | 비스듬히 찍은 바닥 사진을 위에서 본 지도로 펴는 변환 공식. 3×3 숫자 표 하나로 표현된다 | 영상 좌표 → 바닥 좌표 |
| 축척 | 지도 1칸이 실제 몇 m인지. 크기를 아는 물체(노면 표시, 사람 키)로 정한다 | 틀리면 밀도가 제곱으로 틀린다 |
| 머리 높이 평면 | 바닥에서 약 1.5m 떠 있는 가상의 판. 머리 점은 바닥이 아니라 이 판 위에 있으므로 이 판 기준으로 옮겨야 정확하다 | 바닥 기준을 쓰면 위치가 2.4m 밀렸고, 이걸로 0.2m로 줄었다 |
| 카메라 맞추기 | 카메라 높이·내려다보는 각도·확대 정도를 거꾸로 알아내는 것 | E05_035는 사람 키로 맞췄다 (카메라 높이 약 9.2m) |
| 초점거리 | 카메라가 얼마나 확대해서 찍는지를 픽셀 단위로 나타낸 값. 클수록 망원 | 카메라 맞추기의 결과값 |
| 내려다보는 각 (pitch) | 카메라가 수평에서 아래로 몇 도 숙였는지 | E05_035는 34° |
| 최소제곱 | 여러 측정값과 가장 잘 맞는 답을, 틀린 정도의 제곱 합이 가장 작아지도록 찾는 계산법 | 카메라 맞추기 |
| RANSAC | 측정점 중 엉터리를 걸러 내고 믿을 만한 점들로만 답을 찾는 방법 | E04_022 바닥 무늬 찾기 |
| 격자 원점 | 셀 칸을 어디서부터 나누기 시작할지 정하는 기준점 | 화면 끝에서 칸이 잘려 나가지 않게 조정 |

## 4. 평가·통계 용어

| 용어 | 쉬운 설명 | 우리 프로젝트에서 |
|---|---|---|
| 벤치마크 | 모두가 같은 시험 문제로 성능을 비교하는 것 | E1 |
| MAE (평균 절대 오차) | 틀린 개수의 평균. 정답 100명에 90명이라 하면 오차 10. 작을수록 좋다 | E1 목표 SHA ≤ 60, 결과 57.24 |
| MSE / RMSE | 오차를 제곱해서 평균(그리고 제곱근)낸 값. 크게 틀린 경우를 더 무겁게 본다 | E1 보조 지표 |
| 상대오차 | 오차를 정답 대비 비율로 나타낸 것. 정답 40명에 36명이면 10% | E2 목표 ≤ 20% |
| 치우침 (bias) | 평균적으로 많이 세는지(+) 적게 세는지(−) | 보정 판단에 쓴다 |
| 조정용 / 판정용 데이터 | 조정용으로 설정값을 고르고, 처음 보는 판정용으로 채점한다. 시험 문제를 미리 보고 공부하면 점수가 부풀려지는 것을 막는다 | E2를 3장 중 1장 / 나머지로 나눈다 |
| 과적합 | 연습 문제에만 딱 맞춰져서 새 문제에서는 성적이 떨어지는 것 | 보정 계수 k를 썼다가 이 문제로 버렸다 |
| 평균 내기 (평활화) | 들쭉날쭉한 값을 여러 개 평균해 고르게 만드는 것 | 1초마다 0.4초 앞뒤 5장을 평균 |
| p95 | 100번 중 95번은 이 값 안에 들어온다는 뜻. "대부분의 경우 최악" | 알림 지연 p95 ≤ 5초 |
| 기준선 (현재값 유지·직선 추세) | 아주 단순한 예측법. 현재값 유지 = "1분 뒤에도 지금과 같다", 직선 추세 = "지금 오르는 속도대로 계속 오른다" | 60초 예측 E6의 비교 대상 |
| E1 ~ E8 | 우리 실험 번호. E1 모델 성능, E2 밀도 정확도, E5 불안정·유입, E6 예측, E8 속도·지연·안정성 | 기획서 7.2 |

## 5. 프로그램·시스템 용어

| 용어 | 쉬운 설명 | 우리 프로젝트에서 |
|---|---|---|
| 사전 분석 | 시연 전에 영상을 미리 분석해 결과를 파일로 저장해 두는 것 | 시연 중에는 이 파일을 재생만 한다 |
| 재생 | 저장된 결과를 1초에 한 줄씩 꺼내 실시간인 것처럼 보내는 것 | 서버가 한다 |
| Python | AI·데이터 분석에 많이 쓰는 프로그래밍 언어 | 분석 코드 (`src/`) |
| 서버 / 백엔드 | 뒤에서 계산·판정을 하고 화면에 데이터를 보내 주는 프로그램 | Spring Boot (조영준) |
| Spring Boot | Java로 서버를 만드는 도구 모음 | 등급 판정·알림 |
| 프론트엔드 / React | 사용자가 보는 화면 쪽 프로그램. React는 웹 화면을 만드는 도구 | 상황실 대시보드 (나예린) |
| 대시보드 | 여러 정보를 한 화면에 모아 보여주는 관제 화면 | 영상·히트맵·그래프·알림 |
| 히트맵 | 값이 크면 빨갛게, 작으면 파랗게 색으로 칠한 지도 | 영상 위 셀 밀도 표시 |
| API | 프로그램끼리 주고받는 약속된 창구. "이렇게 요청하면 이렇게 답한다" | `docs/api-spec.md` |
| WebSocket | 서버가 화면에 새 소식을 바로 밀어 넣을 수 있는 연결 방식. 화면이 계속 물어볼 필요가 없다 | 1초마다 상태·알림 전송 |
| JSON | 데이터를 `{"이름": 값}` 형태의 글자로 적는 형식. 사람도 읽을 수 있다 | `timeline.json`, 구역 설정 파일 |
| timeline.json | 영상 1개의 분석 결과를 1초 단위로 적은 기록표. 셀마다 밀도·속도·압력·예측값이 들어 있다 | 세 사람이 주고받는 유일한 약속 |
| 규격 (스펙) / 스키마 | 파일에 어떤 이름의 값을 어떤 형식으로 넣을지 정한 약속 | `docs/timeline-spec.md` v0.2 |
| null | "값 없음". 0과 다르다. 0은 "재 봤더니 0", null은 "안 쟀거나 잴 수 없음" | 아직 안 만든 값은 null |
| 가짜 타임라인 | 진짜 분석 전에 그럴듯한 숫자로 만든 연습용 파일 | 서버·화면을 먼저 개발하려고 만들었다 |

### 앞부분·1장 개요

| 용어 | 쉬운 설명 |
|---|---|
| 관제 / 관제요원 / 상황실 | 관제 = 여러 CCTV 화면을 지켜보며 이상한 일이 있는지 살피는 일. 그 사람이 관제요원, 그 방이 상황실이다. 우리 시스템의 사용자다 |
| 지자체 | 지방자치단체. 서울시, 광진구 같은 시·구청. CCTV 관제센터를 운영하는 곳이자 예상 고객이다 |
| 군중이 유체처럼 움직인다 | 사람이 너무 빽빽하면 각자 걷지 못하고 물이 흐르듯 덩어리로 밀려다닌다는 뜻. 군중난류의 앞 단계다 |
| 0.02/s² (단위 1/s²) | 군중 압력의 단위. 밀도(1/㎡) × 속도 분산(㎡/s²)을 곱해서 생긴 단위다. 숫자가 크면 더 위험하다는 것만 알면 된다 |
| 정성 목표 / 정량 목표 | 정성 = 말로 표현하는 목표("알림을 준다"). 정량 = 숫자로 재는 목표("오차 20% 이하") |
| 지표 | 상태를 숫자 하나로 나타낸 값. 체온이 건강의 지표인 것처럼, 군중 압력은 위험의 지표다 |
| 재현 | 논문에 나온 결과를 우리 컴퓨터에서 똑같이 다시 얻어 보는 것. 모델을 제대로 설치했는지 확인하는 방법이다 |
| 논문 (보고)값 | 모델을 만든 연구자가 논문에 적은 성능 숫자. 우리가 직접 잰 값과 구분한다 |
| 시계열 | 시간 순서대로 늘어선 값. 1초마다의 밀도 기록이 시계열이다. 보통 꺾은선 그래프로 그린다 |
| 민감도 (기준값 민감도) | 기준값을 조금 바꾸면 결과(알림 횟수 등)가 얼마나 달라지는지. 기준을 0.02 → 0.03으로 바꿨을 때 알림이 어떻게 변하는지 보여준다 |
| 클립 | 영상에서 잘라낸 짧은 구간 |
| 감지 성능 | "위험 상황을 몇 번 중 몇 번 맞게 알아챘나". 정답 영상이 있어야 잴 수 있는데, 우리는 실제 난류 영상이 없어서 이것을 주장하지 않는다 |
| 실측 | 실제로 잰 값. 예측값과 비교하는 기준이다 |
| 상승 구간 / 급변 구간 | 상승 = 밀도가 꾸준히 오르는 때. 급변 = 갑자기 확 바뀌는 때. 예측은 급변 구간에서 잘 틀린다 |
| 스크립트 | 실행하면 정해진 일을 처리하는 짧은 프로그램 파일. 분석 스크립트 = 영상을 분석하는 Python 파일 |
| 무중단 / 연속 운전 | 오류로 멈추지 않고 계속 돌아가는 것. 30분 반복 재생해도 멈추지 않는지 본다 |
| 실시간 입력 / 스트리밍 | 녹화된 파일이 아니라 지금 찍히는 CCTV 화면을 바로 받아서 분석하는 것. 이번에는 하지 않는다 |
| 탑뷰 / 평면도 | 위에서 똑바로 내려다본 그림. 지도 같은 화면 |
| 실연동 | 실제 지자체 CCTV 시스템에 연결하는 것. 권한과 보안 문제로 이번 범위에서 뺐다 |
| 외부 혼잡도 API | 다른 기관(예: 서울시)이 공개하는 혼잡 정보를 받아 오는 창구 |

### 2장 문제점

| 용어 | 쉬운 설명 |
|---|---|
| 국소 밀도 | 구역 전체 평균이 아니라 아주 좁은 한 지점의 밀도. 평균은 낮아도 한 곳이 빽빽하면 위험하다. 그래서 셀 단위로 잰다 |
| 압축 | 앞이 막혀 뒤에서 계속 밀려 들어와 사람 사이 간격이 더 좁아지는 것 |
| 기지국 데이터 | 휴대폰이 어느 통신 기지국에 붙어 있는지로 그 지역에 사람이 대략 몇 명 있는지 추정한 자료. 넓은 지역은 보지만 골목 하나하나는 못 본다 |
| 실증 과제 | 새 기술을 실제 현장에 설치해 시험해 보는 정부·지자체 사업 |
| (길찾기) 가중치 | 길찾기에서 "이 길은 얼마나 피하고 싶은지"를 나타내는 점수. AI 모델의 가중치(2장)와 이름만 같고 다른 뜻이다 |

### 3장 해결 방안

| 용어 | 쉬운 설명 |
|---|---|
| ρ, V, Var(v), P | 수식에 쓰는 기호. ρ(로) = 밀도, V = 평균 속도, Var(v) = 속도 분산, P = 군중 압력 |
| ρ(t+60) | 지금 시각 t에서 60초 뒤의 밀도. 예측하려는 값이다 |
| 화각 / 화각 경계 | 화각 = 카메라에 찍히는 범위. 화각 경계 = 화면의 가장자리. 사람이 화면 밖에서 들어오는 곳이다 |
| 경계값 근처 깜빡임 | 밀도가 2.9 ↔ 3.1을 오가면 등급이 주의 ↔ 정상으로 계속 바뀐다. 그래서 올릴 때는 2초, 내릴 때는 10초 기다리게 했다 (에어컨이 온도 1도 차이로 켜졌다 꺼졌다 하지 않게 하는 것과 같은 원리) |
| 높은 시점 | 카메라가 높은 곳에서 내려다보는 것. 높을수록 가려짐과 바닥 변환 오차가 줄어든다 |
| 규칙 기반 (↔ 딥러닝) | 사람이 정한 공식(밀도 × 속도 분산)으로 계산하는 방식. 학습 데이터가 필요 없고, 왜 알림이 울렸는지 설명하기 쉽다 |
| 모듈 | 큰 프로그램을 기능별로 나눈 한 덩어리. 인원·밀도 모듈, 흐름 모듈, 예측 모듈이 있다 |
| 공수 / 가용 인력 | 공수 = 일에 드는 노력의 양(인일). 가용 인력 = 실제로 쓸 수 있는 사람·날짜의 총량 |
| 병렬 개발 | 세 사람이 서로를 기다리지 않고 동시에 각자 만드는 것. 가짜 타임라인 덕분에 가능하다 |
| 통합 | 따로 만든 모듈들을 이어 붙여 하나로 돌아가게 하는 것. 보통 여기서 문제가 많이 터진다 |
| 등록 작업 | 코드를 고치지 않고 설정 파일 하나만 추가해서 새 영상·구역을 붙이는 것. 구역 ID 구조로 이렇게 만든다 |
| RPA | Robotic Process Automation. 반복적인 사무 업무를 소프트웨어 로봇으로 자동화하는 기술. 여기서는 같은 기간에 하는 다른 수업 프로젝트를 말한다 |
